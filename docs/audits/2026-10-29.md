## Needs an ADR

- ElastiCache in full-AWS mode before Phase 3 — it has no caller and no health check. Either add the check ADR-0011 requires or drop it until CACHE-2.
- The rights gate as one shared definition — the same predicate is copied in more than 15 places across TS, Python and SQL. A SQL function or view (as `item_minutes` and `github_dependency_technology` already are) would give ING-2 and ARCH-2 one copy, but that changes the ADR-0012 adapter shape.
- Effective concepts of a moment (tag_override, then model tags) — the same case as above: one SQL view versus per-adapter copies.
- What GitHub disconnect deletes — whether `technology_suggestion` rows from a single user's packages must go when that user disconnects (ADR-0024 Consequences).
- Q-P2-42 coverage — the rule filters npm scoped packages and Go modules off public hosts. A single user's unscoped npm and PyPI names, which may be private registry packages, still go to the model provider.
- Secrets store for the GitHub App — ADR-0024 says SSM SecureString, while OPS-1 and the built stack use Secrets Manager. ADR-0024 is ACCEPTED, so only a new ADR can correct its text.
- OPS-3 scope — whether every feature (GitHub, paths, quizzes, reviews) needs its own capability, and whether `ai.notes.daily` should be enforced or removed.
- ADR-0012 and parsing libraries — `books/process.py` and `books/ocr.py` reach pdfplumber through `books/pdf.py`, and `ingest/feed.py` imports feedparser, with no port. Meanwhile, trafilatura sits behind an adapter. Decide whether parsing libraries count as "drivers or SDKs".

Not checked: every TS and Python export line by line (the dead-export scan is heuristic, with grep), the full 3,000-line postgres.py, the UI for AI labels outside feed cards, or anything in .env. Dependency justification was checked by searching names in the docs, so a dependency justified under another name may have been missed.
